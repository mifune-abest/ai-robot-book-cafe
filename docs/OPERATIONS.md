## 3. HTTPS証明書が必要な理由

### 結論

別PCのブラウザからカメラまたは写真ファイルを使うには、子ども用ページを**ブラウザが信頼するHTTPS**で開く必要があります。

```text
http://192.168.x.x:4310/career   → カメラ・写真ファイルとも送信不可
https://192.168.x.x:4310/career  → 信頼設定済み証明書なら利用可能
```

ブラウザのカメラ機能 `getUserMedia()` は、安全な接続だけで利用できる仕様です。また、このアプリは児童写真を暗号化されていないLANへ流さないため、HTTPでは写真ファイル選択も画面とサーバーの両方で拒否します。`localhost` は同じPCの中だけ特例であり、別PCからMacへつなぐ場合には使えません。

### 現在の状態

- `TLS_CERT_PATH` と `TLS_KEY_PATH` は未設定です。
- この作業では、Mac・Windowsの証明書信頼ストアを変更していません。
- 証明書警告を無視して進む運用は採用しません。
- ブラウザの安全機能を無効にする起動オプションも使いません。

### 今後必要な作業

1. 実際に開くMacの固定IPに一致するサーバー証明書を用意する。
2. 証明書と秘密鍵のパスを設定する。
3. 必要な場合、イベント専用の認証局証明書だけを各PCの信頼ストアへ登録する。
4. 4台すべてで、証明書警告が出ず、カメラを使えることを確認する。
5. イベント後に登録した認証局を削除する手順も同時に決める。

証明書信頼ストアの変更は、そのPCが信用する相手を増やすセキュリティ上重要な設定です。**対象PC、追加する証明書、作業目的、削除方法を示し、ユーザーの明示許可を得るまで実行しません。**

プロジェクトには、固定IP用のイベント証明書を作る `scripts/create-local-cert.sh` があります。ただし、固定IPを確認し、証明書作成作業の許可を得た技術担当者だけが使います。このスクリプトは証明書を作るだけで、各PCの信頼ストアは変更しません。作成されるサーバー証明書は7日、認証局証明書は14日で失効するため、作成日とイベント日を確認してください。作成される `rootCA-key.pem` は認証局の秘密鍵なので、Macの外へコピーしません。

`./scripts/start.command` は、証明書と秘密鍵の一致、証明書が24時間以上有効であることを確認します。サーバー起動時には、証明書の対象固定IPが現在のLAN IPと一致しない場合も停止します。表示された `LAN:` 以外のIPを推測して使わないでください。これらの検査は、各PCで証明書が信頼済みかどうかの確認を代替しません。

参考：[W3C Media Capture and Streams](https://www.w3.org/TR/mediacapture-streams/)、[W3C Secure Contexts](https://www.w3.org/TR/secure-contexts/)

## 4. 環境設定ファイルについて

`.env.example` は、安全な設定例と確認項目を記載したファイルです。APIキーなどの秘密情報は入っていません。

Node.jsアプリ本体は `.env` を自動では読み込みませんが、推奨起動の `./scripts/start.command` がプロジェクト直下の `.env` を自動で読み込みます。安全な既定値だけで使う場合は、`.env` を作る必要はありません。

HTTPSなどの設定が承認・準備済みで、`.env` を使う場合だけ次のように準備します。

```bash
cp .env.example .env
# .envを必要な範囲だけ編集する
```

編集後は、次章の `./scripts/start.command` で起動します。手動の `source .env` や通常運用での `npm start` は不要です。証明書をプロジェクト内の `certs/server.pem` と `certs/server-key.pem` に用意した場合は、起動スクリプトが自動検出します。別の場所に置く場合だけ、`.env` の `TLS_CERT_PATH` と `TLS_KEY_PATH` を設定します。

注意事項：

- `.env` はGitへ登録しません。
- 認証情報を画面共有、チャット、ログ、文書へ貼りません。
- `.env.example` には今後も実際の認証情報を書きません。
- HTTPS証明書の設定前に、空の `TLS_CERT_PATH` / `TLS_KEY_PATH` を推測で埋めません。

## 7. ④「きょうのおもいで」の運用

1. スタッフ用画面でテーブル数と予定人数を確認します。
2. `受付を開始` します。
3. 各参加者が、テーブル、ニックネーム、一言を送ります。
4. 「集まった一言」で、テーブル、ニックネーム、一言を確認します。誤った投稿は `削除` し、本人にもう一度送ってもらいます。
5. 欠席が確定した場合は、テーブルの予定人数を修正して保存します。予定人数は、そのテーブルの受付済み人数より少なくできません。
6. スタッフ用画面で「受信人数＝予定人数」を確認します。
7. 全員分がそろってから受付を締め切ります。
8. `全員の絵を生成する` を押します。
9. 人数、ニックネーム、明るい雰囲気、不適切な表現がないことをスタッフが確認します。
10. 問題がない場合だけ手動で公開します。

予定人数が一致しない場合は、人数制限を回避せず、未送信者、重複、誤投稿、欠席を確認してください。現在の実装は、全員分がそろうまで最終画像を作成しません。公開前の画像確認中に投稿を削除した場合、その完成画像は削除され、修正後に作り直す必要があります。

ホスト画面には、AIの実行件数と待ち件数が表示されます。`AI処理：なし（安全に停止できます）` になるまで、④の生成とサーバー停止を重ねないでください。

現在のイベント終了後に次のイベントへ切り替える場合だけ、`新しいイベントを準備` を使います。確認後、④の投稿と完成画像が削除されます。イベント途中では押しません。

## 8. 印刷手順

印刷は自動ではありません。①の結果画面からブラウザ標準の `window.print()` を呼び出し、スタッフが印刷画面で確認して実行します。

1. 結果画像を確認します。
2. 子どもの取り違えがなく、「AIでつくった未来のわたし」と表示されていることを確認します。
3. `印刷` を押します。
4. 表示された印刷画面で、プリンター、用紙、向き、カラー、部数 `1` を確認します。
5. スタッフが印刷を確定します。
6. 紙が実際に1枚出たことと、内容をスタッフが確認します。
7. 印刷物を本人へ直接渡してから、`つぎの人に かわる` を押します。確認ダイアログにもスタッフが回答します。

注意：

- `window.print()` は、その画面を開いているPCの印刷設定を使います。
- PC①から目的のプリンターを選べるよう、前日までにプリンターを登録してください。
- 自動印刷、無人印刷、二重印刷防止の専用キューは未実装です。
- 紙切れ後にボタンを連打せず、OSの印刷待ち一覧を確認します。
- 紙が出る前に `つぎの人に かわる` を押すと、結果画面には戻れません。
- ①の完成画像は45分経過後に定期削除の対象となり、サーバー再起動時にも削除されます。必要な印刷はその場で完了してください。
- 実際の用紙で、色、余白、向き、印刷時間を確認します。
- OSの印刷履歴やスプールに画像が残る可能性があります。イベント後の削除方針に含めてください。

## 9. ログの確認

`./scripts/start.command`は、ログの保存先を表示した後、Codex app-serverの事前確認とWebアプリの画面表示を自動で次へ保存します。

```text
logs/server-YYYYMMDD-HHMMSS.log
```

証明書や `.env` の確認でログ保存先が表示される前に停止した場合は、エラーはターミナルだけに表示されます。

現在のログは、主に起動状態とエラー確認用です。自動ローテーションや管理画面からのログ表示はありません。

ログを見るときは、次を確認します。

| 表示 | 意味 | 対応 |
|---|---|---|
| `Codex app-server: 準備OK (gpt-5.5)` | ログイン済みで指定モデルを利用できる | 続行 |
| `Codex app-server: GPT応答テストOK` | 実際の短い推論に成功した | 続行 |
| `Codex app-serverを利用できません` | ログイン、ネットワーク、利用枠、モデル利用権限、または試験的機能に問題がある | 表示された理由を技術担当者が確認。別モデルへ切り替えない |
| `HTTPS証明書が失効済み...` | 期限が24時間未満 | 本番開始せず、証明書担当者へ連絡 |
| `対象IPと、現在のLAN IPが一致しません` | 固定IPまたは証明書が不一致 | 証明書警告を無視せず、準備済みネットワークへ戻す |
| `EADDRINUSE` | 同じポートを別プロセスが使用中 | 起動済みのサーバーターミナルを探して停止。見つからなければ技術担当者へ連絡 |
| `HTTPは試作確認用で、LAN経由の写真は送信できません` | HTTPS未設定 | 本番開始せず、証明書担当者へ連絡 |

ログを外部サービスやチャットへそのまま送らないでください。送付が必要な場合は、APIキー、個人名、ニックネーム、プロンプトなどが含まれていないか技術担当者が確認します。

## 10. 障害時の復旧

### 10-1. ほかのPCから画面が開かない

1. Macのターミナルに「起動しました」と表示されているか確認します。
2. `localhost` ではなく、起動時に表示された `LAN:` のURLを使います。
3. MacとPCが同じ会場Wi-Fiか確認します。
4. ゲストWi-Fiの端末分離、MacのFirewall、VPNの影響は技術担当者が確認します。
5. IPが変わった場合、証明書警告を無視せず、準備済みのネットワークへ戻します。

### 10-2. カメラが使えない

1. URLが `https://` か確認します。
2. 証明書警告が出ていないか確認します。
3. ブラウザとOSのカメラ権限を確認します。
4. Zoom、Teams、カメラアプリを終了します。
5. ページを再読み込みします。

`http://<MacのIP>:4310` のままでは、権限をオンにしても解決しません。
`しゃしんを えらぶ` もHTTPでは利用できないため、回避策として使いません。

### 10-3. 「AIの準備ができていません」と出る

1. `codex login status`でCodexのログイン状態を確認します。
2. Macがインターネットへ接続できるか確認します。
3. Codexの利用枠と、ログイン中のアカウントで`gpt-5.5`を利用できるか確認します。
4. `./scripts/start.command`で起動し直し、事前確認のエラーを確認します。
5. 別モデルや別のAI基盤へ切り替えません。復旧しない場合はレクリエーションを停止し、技術担当者へ連絡します。

### 10-4. ②で「素材を準備中」と出る

Macのスタッフ用画面で、当日使う素材写真が有効になっているか確認します。仮の素材を勝手に追加しません。

### 10-5. サーバーが止まった

1. 子どもの操作を一度止めます。
2. Macのインターネット接続と`codex login status`を確認します。
3. プロジェクトへ移動し、`./scripts/start.command`で再起動します。`npm start`は使いません。
4. `Codex app-server: GPT応答テストOK`を確認します。
5. 各PCでページを再読み込みします。

現在の復旧上の制限：

- ①と③の進行中セッションはメモリ上だけにあり、再起動すると最初からやり直しです。
- ①の完成画像は再起動時に削除されるため、未印刷分は最初からやり直しです。
- 予期しない停止では、実行中または実行待ちのAI処理が失われる場合があります。
- ④の受付内容と公開状態、登録素材、保存済み画像は `data/` に残ります。④の生成中に停止した場合は受付締切状態へ戻るため、人数を確認して再生成します。
- 印刷済みかどうかはアプリが管理していません。再印刷前に必ず現物を確認してください。

### 10-6. プリンターが止まった

1. 紙、インク、電源、接続を確認します。
2. OSの印刷待ち一覧を確認します。
3. 同じ画像を再度印刷する前に、保留中のジョブがないことを確認します。
4. 自動で別プリンターへ切り替えません。

## 11. 停止手順

1. 子どもの新しい操作を止めます。
2. ④が公開済みか、印刷待ちがないか確認します。
3. ホスト画面が `AI処理：なし（安全に停止できます）` になっていることを確認します。
4. サーバーを起動したターミナルを選びます。
5. `Control + C` を1回押します。
6. 次の表示後、`処理完了を確認して停止しました。` と表示されるまで待ちます。

```text
新しい受付を止めて終了します…
```

`Control + C` 後は新しいAI処理を受け付けず、既に実行中・待機中の処理が終わるまで最大10分待ちます。何度もキーを押したり、ターミナルを閉じたりしないでください。`10分以内に処理を終えられなかったため、強制終了します。` と表示された場合は、進行中の操作をやり直す可能性があるため技術担当者へ連絡してください。

Codex app-serverは処理ごとにローカルの子プロセスとして起動するため、別のAIサーバーを手動停止する操作はありません。

## 12. Codex画像生成と成人テスト

### 現在の運用判断

会話AIと画像AIは、どちらもローカルのCodex app-serverからOpenAIへ接続します。`stdio`はMac内のアプリ間通信であり、データがMacの外へ出ないという意味ではありません。

| 経路 | 現在の扱い |
|---|---|
| Codex app-server / `gpt-5.5` | ①の4つの興味回答、③の会話、④の一言整理に使用。①の性別は送らない |
| Codex組み込み画像生成 / `gpt-image-2` | 成人テスト時に①〜④の画像生成へ使用 |

現在の成人テスト設定は次のとおりです。

```text
IMAGE_PROVIDER=codex
ADULT_TEST_MODE=true
```

このモードでは、①の写真、②の素材画像、③の画像指示、④の一言と人数配置ガイドがCodex経由でOpenAIへ送信されます。④のニックネームは画像生成指示へ含めません。テスト参加者は成人だけに限定し、本人へ目的と外部送信を説明してから撮影します。

### 未成年者での実画像生成を検討する場合

最初に[未成年者画像利用ガイドライン](MINOR_IMAGE_GUIDELINES.md)の全項目を確認します。主な停止条件は次のとおりです。

- 保護者同意だけで有効化しない
- 13歳未満の個人データを扱う前に、対象OpenAI組織・プロジェクト・経路でZero Data Retention（ZDR）を実装し、書面または管理画面で確認する
- 目的、委託先、国外処理、保存・削除、撤回方法、写真なしの代替参加方法を決める
- 全PCで信頼済みHTTPSを確認する
- 印刷・公開前にスタッフが1件ずつ確認する

Codex app-server経路については、現在の実装からZDRの適用状態を確認できません。この経路に児童写真を送ってはいけません。`ADULT_TEST_MODE=true`はこの制限を解除する設定ではありません。

①の職業質問は全5画面です。1画面目では「女の子」「男の子」「どれにもあてはまらない」「こたえない」から任意で選びます。この値はブラウザ内だけで即時利用後に破棄し、GPT、サーバー、職業判定、画像生成へ送らず、質問や職業も性別では変えません。残り4画面では、その時点までの興味回答（初回は履歴なし）を基に`gpt-5.5`が質問と4つの選択肢を毎回生成します。

固定の職業一覧は使わず、4つの興味回答から候補を作り、生成とは別のGPT処理で実在性を再点検した職業を3件提案します。造語・未来の仕事・架空の役、および一般に夜職と呼ばれる職業は候補にしません。夜職は、表記ゆれや主な言い換えも出力後に検査します。ただし、公的な職業データベースとの照合ではないため、本番当日はスタッフが候補名を確認してください。選ばれた職業名は内部の安全分類へ分け、確認済みの服装と背景だけを画像指示に使います。本人の顔・見た目の年齢・体格を保ち、美化、年齢変更、痩身、体型変更、性的な表現は指示しません。印刷物には「AIでつくった未来のわたし」と表示します。

③の質問と4つの選択肢は、選んだジャンルとそれまでの質問・回答を基に`gpt-5.5`が5回すべて毎回作ります。次の質問を作れない場合は固定質問へ切り替えず、再試行画面で停止します。同じ回答の再送で質問が飛ばないよう、質問IDを使って進行を確認します。

実名、学校名、住所、連絡先は写真や入力文と一緒に送りません。撮影画像から位置情報などの付随情報を除き、必要最小限の大きさに変換する現在の処理を維持します。

この文書は法律相談ではありません。実施主体、会場、対象年齢、利用目的、契約、処理地域に応じた個別確認が必要です。

## 13. イベント後のデータ

一部のデータは自動削除されますが、イベント後の全データ削除は自動化していません。

- ①の完成画像は45分経過後に定期削除の対象となり、サーバー再起動時にも削除されます。
- ホストの `新しいイベントを準備` は、確認後に④の受付内容と④の完成画像を削除します。素材写真と設定、①〜③のデータは対象外です。
- そのほかの生成画像、素材写真、印刷履歴等は自動では削除されません。

主な保存先は次のとおりです。

```text
data/state.json       ④の受付内容、設定、素材一覧
data/media/           生成・加工した画像
data/materials/       登録したデニム素材写真
```

イベント終了後は、次の順で扱います。

1. サーバーを停止します。
2. 運営責任者が、削除時刻を確認します。①は45分経過後または再起動後に再印刷できません。
3. 再利用する素材写真と、削除対象の児童データを分けます。
4. バックアップの要否を確認します。無断でクラウドへ保存しません。
5. 対象パスと内容を技術担当者が確認します。
6. ユーザーの明示許可を得てから手動削除します。
7. `data/`、ブラウザのダウンロード、印刷待ち一覧、ログに対象データが残っていないか確認します。

誤削除を防ぐため、この文書には一括削除コマンドを載せていません。現時点では「イベント終了＝自動削除」ではありません。
